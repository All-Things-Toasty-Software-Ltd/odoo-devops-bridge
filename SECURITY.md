# Security Policy

## Reporting a vulnerability

Please do **not** report security vulnerabilities through public GitLab issues or merge requests.

Instead, report them privately to the project maintainers using the security contact provided by the
project.

When reporting a vulnerability, please provide:

* A description of the vulnerability.
* Steps required to reproduce it.
* The affected version, commit, or component.
* Any relevant proof-of-concept information.

Please do not include unnecessary personal information, credentials, passwords, or other secrets in
your report.

## What happens next?

We will review the report and, where appropriate:

1. Confirm receipt of the report.
2. Investigate the vulnerability.
3. Determine the affected versions or components.
4. Develop and test a fix.
5. Release the fix where appropriate.
6. Coordinate disclosure of the vulnerability where necessary.

We ask that security vulnerabilities are not publicly disclosed until maintainers have had a
reasonable opportunity to investigate and address them.

## Third-party dependencies

Security vulnerabilities in third-party dependencies should generally be reported to the relevant
dependency maintainers.

If the vulnerability results from how a dependency is used by this project, please report it to this
project as described above.
